# Syntyr industry site starters (source candidate)

Three **MIT-licensed, framework-independent** multi-page website starters built using the Syntyr source candidate's core CSS and a single opt-in site stylesheet.

| Starter | Pages | Intended use |
| --- | --- | --- |
| `field-service` | Home + services | HVAC, plumbing, roofing, home improvement, maintenance |
| `professional-practice` | Home + care options | Medical/dental/wellness practice content structure; requires professional/regulatory review |
| `saas-developer` | Product + pricing + docs | B2B SaaS, API products, developer tools |

The HTML is hand-editable and requires **no browser JavaScript, build framework, CDN, remote fonts, or images**. Every starter is responsive, includes skip navigation, native disclosure FAQs, semantic landmarks, and visible focus styles.

## Preview in the repository

From repository root:

```sh
python3 scripts/build.py --check
python3 -m http.server 8000
```

Open `http://localhost:8000/examples/industry-sites/`, or directly visit a starter's `index.html`.

## Export a self-contained website

```sh
python3 scripts/package_industry_sites.py --output /tmp/syntyr-starters
```

Each ZIP contains all pages, `assets/syntyr.core.css`, `assets/site.css`, and this README. Extract a ZIP and host its contents at any path on a static server; links and stylesheets are relative, so no rebuild is needed. The archive includes CSS from the **current repository source candidate**, not necessarily the published npm release.

## Before publishing a customer website

1. Replace every fictional brand, sample service description, `.example` contact address, CTA, and any illustrative prices. Connect a real, verified lead-capture or booking service; these starters intentionally **do not** submit personal or medical information.
2. Add authentic photos and permission-cleared logos or reviews; verify certifications, service areas, business addresses, operating hours, pricing, accessibility claims, and regulated industry advertising requirements.
3. Remove the `noindex` metadata only when the finished public site is ready to be indexed. Add verified canonical URLs, social images, business structured data, legal/privacy pages, and consent requirements as appropriate.
4. Review keyboard behavior, contrast, reflow at 320px and 200% zoom, browser accessibility, and any added third-party integrations.
5. If using the medical practice starter, connect an approved privacy/compliance-reviewed scheduler rather than placing patient intake or medical history in a static contact form.

The three templates are illustrative foundations, not revenue projections or proof of completed integrations. No checkout, account creation, scheduling, CRM, or backend is included.

## Architecture

- Source files: `examples/industry-sites/<name>/*.html`
- Shared optional presentation: `examples/industry-sites/site.css`
- Syntyr source of truth: `src/`; the bundled `dist/syntyr.core.css` is generated by the repository build
- Packaging: `scripts/package_industry_sites.py` (stdlib only)
- Contract tests: `python3 -m unittest tests.test_industry_sites -v`

Keep industry presentation scoped to `.industry-site`; don't add industry-specific rules to Syntyr core.
