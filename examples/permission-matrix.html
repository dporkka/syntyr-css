Workspace policy preview

These are illustrative defaults. You can change the Viewer and Editor checkboxes locally, but changes are not saved and do not grant or revoke permissions. The Administrator column is a disabled example of a fixed system role.

The scrollable table region can receive keyboard focus. Labels announce both the role and capability. Disabled controls are not submitted by browsers; a server must derive effective permissions from its own trusted policy.

Server integration

  1. Read authenticated actor and tenant from the server session, not hidden form fields.
  2. Authorize role updates using trusted policy, including restrictions on modifying administrator privileges.
  3. Validate all submitted capabilities, enforce CSRF protection and reject stale policy versions.
  4. Persist atomically, audit the actor and policy diff, and show truthful success or error feedback.

Syntyr provides presentation, not authentication, authorization, persistence or audit logging.

Reading this matrix

Checked means the illustrative role includes that capability.

Unavailable describes a capability omitted from that role. Color is not the sole indicator; every control has an explicit checked state.

Why is the administrator column disabled?

A fixed system role is one possible product policy. If your product permits editing it, remove disabled states and implement a reviewed authorization workflow. Do not infer actual permissions from the HTML.
