Media & Entertainment recipes

Syntyr's optional Media & Entertainment CSS is an original, framework-neutral, zero-runtime module for editorial catalogs, film/TV-inspired landing pages, product galleries, libraries and media portfolios.

Installation

Load Syntyr core first, then the optional media module:

<link rel="stylesheet" href="/dist/syntyr.core.css">
<link rel="stylesheet" href="/dist/syntyr.media.css">

The unreleased source-candidate npm package also exports @syntyr/css/media.css. Unlike core and all CSS, this module is always opt-in. The zero-JavaScript example collection includes fictional titles and original SVG art with no network requests.

CSS primitives

  • syn-media-shell: page shell. Use on the same element as syn-root, or on a descendant.
  • syn-media-navigation, syn-media-navigation__desktop, syn-media-navigation__mobile, syn-media-navigation__link: responsive navigation with one landmark for desktop and one for mobile. The 48rem breakpoint shows only the corresponding nav; the mobile fixed bar provides safe-area padding.
  • syn-media-hero, syn-media-hero__content, syn-media-hero__title, syn-media-hero__eyebrow, syn-media-hero__description, syn-media-hero__actions: cinematic hero with configurable visual and contrast-preserving gradient. Set --syn-media-hero-image to a gradient or a licensed background image, and --syn-media-hero-position to a focal point.
  • syn-media-card, syn-media-card__link, syn-media-card__visual, syn-media-card__badge, syn-media-card__title, syn-media-card__meta, syn-media-card__action: media cards with image aspect ratios. Set --syn-media-card-ratio to 16 / 9, 1 / 1 or 2 / 3. Place buttons outside the anchor link: nested links/buttons are not valid interaction semantics.
  • syn-media-rail: horizontally scrollable, touch-friendly row of cards, with scroll-snap proximity and card sizing via --syn-media-rail-item-size. Rails and cards can be composed directly under syn-root without a media shell; they provide local fallbacks for gap, item size and poster aspect ratio.
  • syn-media-section, syn-media-section__heading, syn-media-search: supporting title, section and search-form styling.

Native scroll buttons and markers (opt-in)

In the unreleased alpha.5 source candidate, an existing syn-media-rail can opt into browser-generated carousel controls with no JavaScript. The existing Scroll Snap row remains scrollable by touch, trackpad, keyboard and the browser's normal horizontal overflow behavior in Firefox, Safari and browsers without CSS Overflow Level 5 carousel pseudo-elements.

Add syn-media-rail--controls for previous/next scroll buttons. Optionally add syn-media-rail--markers for one clickable position marker per labeled direct child. Each marker needs data-syn-scroll-label with a distinct, human-readable name (avoid empty or repeated names). This is the syn-media-rail CSS primitive, not a separate JavaScript carousel widget.

<div class="syn-root">
  <div class="syn-media-rail syn-media-rail--controls syn-media-rail--markers"
       role="region" tabindex="0" aria-label="Customer stories">
    <article data-syn-scroll-label="Customer story: North">
      <a href="/stories/north">North</a>
    </article>
    <article data-syn-scroll-label="Customer story: South">
      <a href="/stories/south">South</a>
    </article>
  </div>
</div>

Both classes are progressive opt-ins. Supporting Chromium-family browsers create native scroll buttons, disable buttons at scroll boundaries, and expose marker navigation. Browsers without support ignore the pseudo-elements and keep the native Scroll Snap rail and horizontal scrolling. Browser and OS settings can hide scrollbar painting; keyboard and trackpad/wheel scrolling remain available. CSS anchor positioning places the generated controls; absent anchor support, they are not generated by Syntyr. There is no autoplay, looping, synchronization, remote fetching or scroll-driven application state. Use a host enhancement only if required and test keyboard and screen-reader behavior on supported engines.

A large marker group is constrained to a locally horizontally scrollable row, avoiding page-width overflow at narrow viewports. Use syn-media-rail--controls without the marker modifier for many cards; even with local scrolling, dozens of markers become noisy. Marker labels are CSS generated and are not necessarily translated by translation tools: localize data-syn-scroll-label in your HTML output. For meaningful content, also retain a real link within each card.

Browser references: MDN CSS carousels and CSS scroll snap.

Real images

Replace the original sample SVG illustrations with real images in production. For a typical poster, place an img inside syn-media-card__visual, with width, height, loading="lazy" and decoding="async". Provide meaningful alt text where the picture contains additional information, or alt="" when adjacent visible text fully conveys the same information. Only use licensed media art.

Keyboard, motion and contrast

  • Keyboard support uses native links, buttons, inputs and tab focus. Give a meaningful syn-media-rail role="region", tabindex="0" and aria-label so users can identify and scroll the horizontal region even without pointing devices. Native link focus continues through each title.
  • reduced motion preference disables poster zoom and auto-scrolling. There is no autoplay, scripted scroll or mandatory JavaScript.
  • Forced colors mode removes the visual hero overlay and retains visible borders and focus outlines. Test your product's image and theme contrasts.
  • At narrow screen widths, the nav switches at 48rem and reserves padding for the bottom navigation. Browser zoom remains available.
  • The demo's search input is intentionally disabled. To offer functional search, provide a framework or backend integration (HTMX, Go, React, etc.) rather than presenting a fake search interaction.
  • The CSS layer is syn.recipes and all selectors require a syn-root ancestor. It shares the --syn-* token system without requiring a new theme.

Maintenance

Do not load the media module in enterprise admin screens that do not use it. No fonts, runtime dependencies, third-party images, or JavaScript are shipped with this optional recipe. See the live example and HTML guide.
