Use Syntyr with WordPress, Wix, Shopify, Webflow, Framer and other platforms

Syntyr styles your own HTML, without JavaScript, build tooling, framework dependencies, plugins or proprietary APIs. It does not automatically reskin native CMS widgets, checkout, platform data services or their editor interfaces.

Platform-by-platform setup guides

Each guide covers benefits for that platform, installation steps, real HTML examples, limitations, and checks for the published site. These are portable CSS recipes, not official platform plugins, partnerships or end-to-end certification for every platform account.

Pick the correct CSS

Use syntyr.core.css for a site that Syntyr owns. For a Syntyr feature inside an existing site or CMS theme, use syntyr.embed.css from the unreleased alpha.5 source candidate. It contains the same core tokens and components but removes their outer CSS cascade layers. A typical unlayered theme declaration otherwise overrides all normal layered rules, regardless of specificity. The embed CSS remains scoped to the syn-root class. It does not guarantee victory over more specific host selectors or !important, and it does not inject CSS across iframe boundaries.

Release boundary: syntyr.embed.css is not in the published immutable alpha.4 release; build it locally using python3 scripts/build.py and self-host dist/syntyr.embed.css for alpha.5 development. Do not invent an alpha.5 CDN URL. For production today, alpha.4 syntyr.core.css is published, but its layered cascade needs validation against each host theme. Do not load both core and embed stylesheets together.

Load the stylesheet once in your page's <head>:

<link rel="stylesheet" href="/assets/syntyr.embed.css">

Then place this content in a platform-provided visible HTML block or theme template (not in a head-code field):

<section class="syn-root" data-syn-theme="studio" aria-labelledby="syntyr-title">
  <div class="syn-panel">
    <h2 class="syn-heading" id="syntyr-title">Our services</h2>
    <p class="syn-muted">A self-contained, accessible feature.</p>
    <a href="/services" class="syn-button syn-button--primary">Explore</a>
  </div>
</section>

Keep syn-root on the component wrapper, not the site's <body>. Do not apply the optional syn-semantic class to the whole CMS document or use syn-page unless a full-height page is intended. Replace the sample URL with your own site paths. For production, prefer a self-hosted, immutable versioned asset over an unversioned CDN.

WordPress

Copy the alpha.5 build's CSS into a child theme at assets/syntyr.embed.css, then adapt the WordPress enqueue example into the child theme's functions.php or a site-specific plugin. Add the example <section> through a Custom HTML block. Do not assume a <link> tag pasted into a post will be preserved; permissions determine HTML sanitization. On block themes, Additional CSS may be available through Site Editor > Styles, but is less convenient for a full distribution. WordPress.com and managed hosts can restrict theme access and custom code.

Shopify

Copy the CSS to theme assets/syntyr.embed.css, then load once in layout/theme.liquid inside <head>:

{{ 'syntyr.embed.css' | asset_url | stylesheet_tag }}

Copy the Shopify feature section into theme Sections and insert “Syntyr feature” in the theme editor. The sample uses editable text, URL settings, and HTML-escaped outputs. This targets Online Store themes, not checkout extensions. Avoid pasting the CSS into Shopify's Custom CSS field: its 1,500-character theme-wide and 500-character section limits, as well as forbidden at-rules, make it unsuitable for a complete CSS distribution.

Wix / Wix Studio

For a visible standalone feature, add an Embed HTML element; this is an iframe. Paste a complete iframe document containing the stylesheet link and Syntyr <section>:

<!doctype html>
<html lang="en">
<head>
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <link rel="stylesheet" href="https://YOUR-HOST.example/syntyr.embed.css">
</head>
<body>
  <section class="syn-root" data-syn-theme="studio">
    <div class="syn-panel"><h2 class="syn-heading">Hello from Syntyr</h2></div>
  </section>
</body>
</html>

Use your own HTTPS-hosted stylesheet, and size the embed so its contents aren't clipped. Styling in the parent Wix document cannot reach into the iframe. Wix dashboard Custom Code is not the same as Velo/site code: it cannot access Wix APIs and must not rely on Wix-generated classes or page DOM nodes remaining stable. Custom elements and Velo can provide deeper integrations but are optional and platform-specific.

Webflow

Add the link tag to Site Settings > Custom Code > Head or page-level Head, then insert the feature markup using a Code Embed. Publish the site to confirm behavior. Embedded code and CSS may conflict with the native Designer, and custom-code permissions vary by plan.

Framer

Add the link tag to Project Settings > Custom Code, placed in the head, and insert the feature markup using a supported Embed or code component. An isolated iframe needs the stylesheet inside its own document. Verify the published URL rather than assuming the editor canvas reflects external code.

Other builders

Squarespace Code Blocks, Ghost HTML cards, HubSpot CMS custom modules, Drupal/Joomla theme templates, and other builders can use the same asset + syn-root recipe when they allow both CSS and custom HTML. If only an iframe is supported, host an HTML page that links Syntyr inside the frame. If a platform forbids custom CSS or visible HTML, do not target private generated classes: native widgets are not compatible by default.

Verify on the published site

  1. Verify the CSS URL succeeds, is served as CSS and matches the installed version.
  2. Compare native site buttons/cards outside syn-root before and after.
  3. Test the Syntyr feature at 320px, with keyboard navigation, reduced motion, forced colors, and the host theme's global typography/forms rules.
  4. For an iframe, check sizing, accessibility, asset origin, CSP and sandboxing.
  5. Host theme CSS with higher specificity/!important may still need a local, narrowly scoped override; the embed distribution addresses cascade-layer precedence, not every possible site builder rule.
  6. Recheck after builder or theme updates; no provider account integration has been end-to-end verified by this source-only compatibility suite.
