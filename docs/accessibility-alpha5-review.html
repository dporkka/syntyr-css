SYNTYR alpha.5 — outstanding accessibility review

This report distinguishes the most recent automated findings from older pixel-sampling evidence. It is not a WCAG certification.

Fresh exact-head audit: 70ec764 (November 18, 2026)

Newest automated source snapshot, not alpha.5 release approval. This source candidate includes the focused fixes to keyboard-inaccessible documentation code blocks and a prohibited ARIA label on a nested form footer.

  • Chromium with Playwright 1.65.2 and pinned axe-core 4.10.3, checksum SHA-256 880970c081707360e64f34cea25ff91892f5bc95675b0776925b9709dd8a68bb: 37 pages, zero confirmed automated violation nodes, and 15 incomplete color-contrast rule results comprising 165 element targets.
  • Baseline 985fe01 had two serious scrollable-region-focusable nodes in the design-principles guide and one aria-prohibited-attr incomplete footer. The source candidate eliminated all three; the 165 remaining incomplete targets concern contrast, not confirmed failures.
  • The reconciled source passed 1,035 Python tests (one skipped), generated-document/metadata/registry/CSS/Cloudflare and maintenance checks. Chromium/Firefox verified focused ArrowRight keyboard scrolling of the code examples at 320px/390px (also forced-colors emulation) and 1280px.
  • Conservative pixel triage at 1280/390/320px produced 495 observations: 459 screenshot samples above text thresholds, 9 opaque computed placeholder pairs above threshold, and 27 non-text entries, with zero sampled below or near threshold. The lowest sampled text result was approximately 5.19:1 against the ordinary-text 4.5:1 threshold, on the business example kicker.

Still open: manually adjudicate each of the 165 axe-incomplete contrast targets in real painted, interactive states. Samples are not glyph-level certification and may miss gradients, overlays or focus/hover appearance. True 200%/400% browser zoom, native OS high contrast, screen-reader testing and representative application flows are not proven. The unpatched high-severity picomatch advisory in optional Expo development tooling remains separate and unresolved. Do not tag or publish alpha.5 on these automated results alone.

For reproduction, run the pinned local axe script with tests/axe_audit.py, then pass its JSON report to tests/contrast_pixel_triage.py at widths 1280, 390 and 320. The JSON reports were retained outside the source tree at the audited revision. Repeat the audit when main advances.

Re-sampling found 456 observations above sampled text thresholds, 27 non-text, 3 unsampled, 0 sampled-below-threshold and 0 narrow-margin at the three widths. This prioritizes risk but does not resolve any axe inconclusive as a certified pass.

After rebasing the candidate onto newer main commit 7e5c14d, a fresh axe-core scan reported 160 inconclusive elements across 27 pages. The three-width repeat (480 observations) contained 450 sampled-above, 27 non-text, 3 unsampled placeholder and zero sampled-below or narrow-margin entries. This is a newer snapshot than the 162-target baseline, not an assertion that all 160 remaining elements have been manually adjudicated.

A still newer rebase onto main commit c726dc3 (which restored the native-APIs audit page) produced 161 inconclusive elements on 28 pages at candidate revision 912e431, with 14 incomplete rule results and zero confirmed violations. This replaces the 160-element figure as the newest candidate triage, but all 161 inconclusive elements still require human review.

No below-threshold result was found at the sampled positions using 4.5:1 for ordinary text and 3:1 for large/bold text. The closest result was the Studio header badge at 1280 px (4.65:1 against a gradient); it should receive priority in visual review because its margin above 4.5:1 is narrow.

Method: Chromium 156.0.8078.4 at device scale factor 1, Playwright 1.65.2, a 1280/390/320 px page viewport, getComputedStyle().color for text foreground, text-node Range.getClientRects() for location, and full-page screenshots with glyph fill temporarily transparent to reveal underlying gradients. Five horizontal by three vertical points per text fragment were sampled and compared using the WCAG sRGB luminance/contrast formula. These are sampled background pixels, not a guarantee about every pixel beneath every glyph. Fixed viewport and static states do not establish behavior across zoom, hover, focus or user-customized themes.

The sole 1280 px unsampled target was #dispatch, a textarea without ordinary text nodes; its computed placeholder color rgb(173,191,202) against background rgb(8,15,25) measures 10.14:1, and its input text color measures 17.93:1. At 320/390 px, the 14 additional unsampled targets were horizontally off-screen cells/statuses inside the deliberately scrollable examples/resources.html table. These cells were sampled at 1280 px, but their mobile scrolled state still warrants manual inspection.

Interpretation: this triage found no obvious color-contrast regression in the sampled cases; it does not close the 325 manual-review targets or certify WCAG AA. Background sampling can miss local gradient extrema, overlapping pseudo-elements, text-shadow effects, embedded graphics, and interactive states. The actual screen reader, real zoom, high-contrast mode, and representative-product checks below remain open.

Manual verification protocol

For each flagged element, record selector, theme, browser, viewport/zoom setting, sampled foreground and effective background, measured contrast and screenshot. Test the lowest-contrast part of each gradient. Apply WCAG thresholds of at least 4.5:1 for regular text and 3:1 for large text and applicable essential UI graphics. Check hover, focus, disabled, selected and nested-theme contexts.

Earlier automated browser evidence covered 126 viewport cases across Chromium/Firefox/WebKit and 168 enlarged-text reflow cases on a historical commit. These figures are not the latest branch coverage. The Chromium forced-colors primary-link screenshot and focus tests passed for all seven palettes in that snapshot. None of these checks substitute for native Windows High Contrast or other OS-level modes, real browser zoom, or a screen reader.
